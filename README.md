1.	¿Por qué es mala práctica usar SELECT * en producción? Mencioná al menos dos razones concretas (rendimiento, mantenibilidad, seguridad).
Usar SELECT * en consultas que forman parte de un sistema en producción es de mala practica en cuento a rendimiento debido a que trae todas las columnas de la table, aunque sean necesarias solo algunas. Esto conlleva más tiempo de procesamiento y que las conultas se vuelvan más lentas. Un ejemplo puede ser que solo se necesita mostrar product_name y total_amount, en ese caso usar SELECT * genera a la base de datos a leer y mostrar el resto de las columnas (order_id, order_date, customer_id, product_id, category, quantity, unit_price) sin que fueran necesarias. Otra cuestión es el mantenimiento ya que, por ejemplo, si alguien agregar otra columna, como podría ser una que muestre los descuentos aplicados, las consultas con SELECT * traerían esa columna sin que se haya indicado la misma. Esto podría afectar el código y generar errores. 
2.	¿Por qué son importantes los alias para un stakeholder no técnico? Explicá con un ejemplo concreto cómo un alias transforma total_amount en algo que cualquier persona del área de finanzas puede interpretar directamente.
Los alias son importantes porque los nombres como total_amount o unit_price pueden no ser claros para aquellos que sean ajenos a la parte de programación y, utilizando un alias, se puede indicar un nombre claro que personas de otras áreas puedan comprender. En el ejemplo de total_mount, esta columna podría ser renombrada a monto_total_vendido para que una persona de financias pueda comprenderlo directamente con solo leer la descripción y no requiera que otra persona se lo explique.
